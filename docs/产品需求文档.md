# VibeFit 产品需求文档

> 版本：2.0 · 状态：在研 · 最后更新：2026-08-22
> 设计依据：`reference/综合训练计划.xlsx`（三套分化方案 + 动作库 + 组数建议）

## 1. 产品定位

VibeFit 是一款**个人科学健身训练指导工具**，将 `reference/综合训练计划.xlsx` 中成熟的健身房分化训练方法论结构化为可执行、可记录、可追溯的训练计划与训练日志。

### 设计原则

- **离线优先**：训练发生在健身房等弱网环境，所有计划与记录能力必须离线可用
- **数据自主**：训练记录归属用户本人，可随时导出，不锁死在云端
- **多端一致**：同一套训练计划与记录在 PWA 与 Android App 上完全一致

## 2. 功能性需求

### 2.1 训练计划管理

#### FR-1.1 计划模板库

内置三套分化方案模板，内容与 `reference/综合训练计划.xlsx` 完全一致。用户选择一套跟练即可。

**设计依据**：模板按**协同肌同日训练**原理编排——当主练肌群的复合动作已附带激活某些协同肌时，同日补练少量协同肌组数即可，无需单独安排一天。参考文件对每个训练日的原理说明：

| 训练日 | 参考文件原理说明 |
| --- | --- |
| 背 + 肩后束 + 肱二头 | 练背会有肩伸（肩后束）、肩水平外展（肩后束）、肘屈（肱二头肌），所以练背后补练肩后束、肱二头即可 |
| 胸 + 肩前中束 + 肱三头 | 练胸会有肩屈（肩前束）、肩水平内收（肩前束）、肘伸（肱三头肌），所以练胸后补练肩前束、肱三头即可 |
| 背 + 肱二头（肩单练版） | 同上原理，肩后束在肩日单独强化 |
| 胸 + 肱三头（肩单练版） | 练胸会有肘伸（肱三头肌），补练肱三头即可 |
| 背 + 肩后束（手臂单练版） | 练背会有肩伸、肩水平外展（肩后束），补练肩后束即可（肱二头在手臂日单独强化） |
| 胸 + 肩前中束（手臂单练版） | 练胸会有肩屈、肩水平内收（肩前束），补练肩前束即可（肱三头在手臂日单独强化） |

**三套分化方案**：

| 中胸 | 10 组 | 12 组 |
| 肩前束 / 肩中束 | 选 1 个 总共 5 组 | 选 1–2 个 总共 6–8 组（手臂版）/ 选 2 个 总共 8–10 组（肩单练版） |
| 肩后束 | 选 1–2 个 总共 6–8 组 | 选 1–2 个 总共 8–10 组（肩单练版） |

| 肱三头 | 选 1 个 总共 5 组 | 选 1–2 个 总共 6–8 组（肩单练版）/ 选 2 个 总共 8–10 组（手臂单练版） |

| 背（下拉/划船）、腿臀、腹 | 选 1–2 个 总共 6–8 组 | 同（始终为主练） |

##### 补充说明（使用指引，非自动功能）

以下内容来自参考文件，是用户使用模板时的参考指引，**当前产品不自动执行**，用户需自行参照：

- **腿臀循环**：股四头肌、腘绳肌、臀大肌三个大肌群难以一次全练，按性别 + 轮次循环侧重：
  - 男性：第 1 次腿日侧重股四头肌 + 兼练动作，第 2 次侧重腘绳肌 + 兼练动作
  - 女性：第 1 次腿日侧重臀大肌 + 兼练动作，第 2 次侧重腘绳肌 + 兼练动作
  - 兼练动作（哈克机、倒蹬机、箭步蹲、史密斯深蹲）同时刺激股四头肌与臀大肌
- **女性注意**：女性不太需要练胸大肌，每两轮分化时拿一轮跳过练胸日（练胸频率减半）；腹部训练男性要练，女性偶尔练下即可

#### FR-1.2 自定义计划

- 用户可从零创建空白计划，自由编排训练日、阶段、动作组
- 可为动作组添加/删除动作：从内置动作库（见 2.5）选择
- 可编辑每个动作的目标组数、目标次数、组间休息秒数、有氧目标时长
- 可调整动作顺序、训练日顺序、训练日激活/停用

#### FR-1.3 计划切换

- 同一时刻只有一个"当前激活计划"
- 切换激活计划后，"今日训练"页立即反映新计划内容
- 删除计划需二次确认

### 2.2 训练执行与记录

#### FR-2.1 训练会话

- 一次训练从"开始训练"到"结束训练"为一个**训练会话**（TrainingSession），归档到历史
- 会话状态：未开始 → 训练中 → 已暂停 → 结束
- 会话记录训练总时长（基于时间戳，暂停不累计）、开始/结束时间、所属计划/训练日快照
- 异常中断（闪退、刷新）后提供恢复选项：继续（排除中断期）/ 在最后检查点结束 / 放弃

#### FR-2.2 力量训练记录

- 每个力量动作以卡片展示：动作名、示意图、目标组数×次数、已完成组记录
- 每组记录：实际重量、实际次数、可选 RPE（1–10 主观用力程度）
- 配重策略来自参考文件，产品按以下区间配置 `targetReps`：

| 配重档位 | 重复次数 | 用途 |
| --- | --- | --- |
| 中等配重 | 6–12 次 | 大部分时候使用 |
| 小配重 | 12–15 次 | 偶尔适应新动作时使用 |
| 大配重 | 3–5 次 | 偶尔过渡力量时使用 |

- 支持"加练"：在目标组数之外追加一组
- 支持取消最近已完成的组（同步停止其休息计时器）
- 力量动作间切换时，休息计时器自动替换为新动作的休息秒数

#### FR-2.3 有氧训练记录

> **产品扩展，非参考文件内容**：有氧训练（跑步机/椭圆机/划船机）不在 `reference/综合训练计划.xlsx` 中，是 VibeFit 自主扩展的功能。

- 有氧动作独立成区，可与力量训练穿插进行
- 每个有氧器械支持：开始 → 暂停 → 继续 → 完成记录 / 取消
- 单个器械运行时独立计时（不影响整场训练总时长）
- 同一时刻最多一个有氧动作运行；开始新有氧前需完成或暂停当前有氧
- 完成时录入实际指标（依器械类型不同）：
  - **跑步机**：时长、速度（km/h）、坡度（%）、距离、热量
  - **划船机**：时长、距离、平均配速（秒/500m）
  - **椭圆机**：时长、距离、阻力等级
- 有氧训练状态在页面切换、应用重启后保持一致（不丢失计时）

#### FR-2.4 训练计时器

- **训练总计时**：从"开始训练"累计，暂停不累计，继续接续；基于时间戳，不依赖应用前台时长
- **组间休息计时**：完成力量组后启动，剩余 0 自动结束
- 组间休息秒数来自参考文件，产品按部位配置 `restSeconds`：

| 部位 | 建议休息 |
| --- | --- |
| 胸 / 背 / 臀腿 | 2–3 分钟（臀腿可以更长一点） |
| 肩膀 / 手臂 | 2 分钟 |
| 最低下限 | 不应低于 1.5 分钟 |

> 参考文件原文："可自行酌调。"

- 暂停整场训练时清空/暂停当前休息计时器
- 结束/放弃训练时清空休息计时器

#### FR-2.5 结束训练保护

- 结束训练前若有进行中/暂停中的有氧动作，提示用户确认（防止丢失有氧数据）
- 结束时会话写入历史，包含全部力量组记录与有氧记录
- 暂停中的会话不自动归档；卡死会话需用户在恢复对话框中显式处理

### 2.3 训练历史与回顾

#### FR-3.1 历史列表

- 按日期倒序分组展示训练会话
- 每条摘要：日期、计划名、训练日名、总训练时长、力量组总数、有氧总时长
- 支持关键词搜索（动作名、计划名、笔记内容）

#### FR-3.2 详情查看

- 力量部分：每个动作的每组记录（重量、次数、RPE）
- 有氧部分：每个器械的时长、距离、速度、坡度、热量、配速等
- 总训练时长、开始/结束时间

#### FR-3.3 笔记

- 每条历史会话可附加自由文本笔记
- 笔记可在详情页编辑保存
- 笔记纳入搜索范围

### 2.4 数据管理与多端同步

#### FR-4.1 本地数据导出/导入

- 一键导出全部数据为 JSON 文件（计划 + 历史 + 设置）
- 从 JSON 文件恢复数据，导入前预览并二次确认
- 导入/导出格式在 PWA 与 Android 间完全一致，可互导

#### FR-4.2 云端备份（可选）

- 邮箱验证码登录后，可将本地全部数据作为**全量快照**上传云端
- 可从云端拉取最新一份快照恢复到本地（覆盖确认）
- 备份是全量快照模式，非增量同步；按"账号 + 设备"维度存储最新一份
- 同一账号可在 PWA 与 Android 上分别推送/拉取，后端不区分客户端类型

#### FR-4.3 数据清除

- 清除全部本地数据，需二次确认
- 生产环境走确认流程，开发环境可直连删除数据库

### 2.5 动作库

- 力量动作按参考文件的部位分类：背（下拉/划船）、肩后束、肱二头、胸（中胸/下胸/上胸）、肩前束、肩中束、肱三头、腿臀（股四头肌/腘绳肌/臀大肌/兼练动作）、腹
- 有氧器械：跑步机、椭圆机、划船机（**产品扩展，非参考文件内容**）
- 每个动作标注训练的肌群（如"杠铃卧推"→ 胸 + 肱三头）
- 每个力量动作配套示意图 PNG，按 `exerciseId` 显式映射
- 有氧器械暂无示意图，UI 用品牌色块占位
- 动作库固定，用户不能自建动作，但可在计划中自由组合

## 3. 非功能性需求

### 3.1 离线优先

- 训练计划管理、训练执行、训练历史、本地数据导出/导入全部离线可用
- 无网络时仅云端备份与邮箱验证码失败，本地功能不受影响
- 训练计时基于时间戳，应用切后台/锁屏后回前台可准确接续

### 3.2 多端一致性

- PWA 与 Android App 共用同一套前端代码与数据契约
- 两端导入/导出的 JSON 格式完全一致
- 后端 API 不区分客户端类型

### 3.3 数据安全

- 不收集设备标识、不上报使用数据
- 验证码邮件仅用于登录
- 用户数据可随时导出/清除

## 4. 范围与非目标

### 4.1 当前不做

- 社交功能（关注、点赞、分享训练成果）
- 营养/饮食记录
- 体重/体脂等身体指标跟踪
- AI 教练/动作纠错/动作识别
- 付费会员/订阅
- 自动生成训练计划（计划由用户基于模板创建或自定义，产品不替用户做分化决策）

### 4.2 不为 Android 引入独立后端

- Android 与 PWA 共用同一后端 API
- Android 端原生能力（本地通知、振动、文件系统）仅作为前端能力，不改变后端契约
