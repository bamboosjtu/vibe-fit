# UI 设计文档

VibeFit 的 UI 设计文档按页面/模块组织，每个页面一个子目录，目录内放置 `ui-brief.md` 作为产品交互契约。

## 目录结构

```text
docs/ui/
├── README.md          本文件
├── today/             今日训练页
├── plans/             计划页
├── history/           历史页
└── settings/          设置页
```

## 维护规则

1. 每个页面的 `ui-brief.md` 必含：页面目标、用户任务、页面结构、数据绑定、状态机、交互规则、响应式规则、加载/空/异常状态、无障碍要求、验收标准。
2. 数据绑定章节必须引用 `pwa/frontend/src` 下的具体类型或 ViewModel，不得用「某对象」模糊描述。
3. 文档与代码冲突时，以代码中的业务模型为准并同步修订文档；不得在 UI 中写入无数据来源的假值。
4. 原型图统一放在 `docs/prototype/` 或 `docs/assets/`，文档中以相对路径引用，不要复制图片到多个目录。
5. 跨页面共享的设计令牌（颜色、圆角、间距）见 `docs/design-system.md`，本目录不重复定义。
6. 修改页面 UI 前先读对应 `ui-brief.md`；新增页面时新建子目录并补一份 brief。
7. 简短聚焦，每个文档只描述核心规则，避免重复设计系统内容。
