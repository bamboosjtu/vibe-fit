# VibeFit UI Brief

> 状态：Baseline v1  
> 适用范围：`pwa/frontend` 的 H5/PWA、后续微信小程序 WebView/H5、Capacitor Android 复用界面  
> 设计参考：[`原型图.png`](./原型图.png)  
> 配套规范：[`design-system.md`](./design-system.md)

## 1. 文档目的

本文档定义 VibeFit 的页面目标、信息层级、交互语义和验收标准。它回答以下问题：

1. 用户在训练中最先看到什么；
2. 用户如何开始、记录、暂停、恢复和结束训练；
3. 训练上下文、阶段、动作和组记录如何组织；
4. 哪些状态必须持久化，哪些仅用于临时显示；
5. 设计稿与实现发生冲突时，按什么规则判断。

本文档是产品和交互层的约束，不替代业务模型、数据库设计和 API 文档。

---

## 2. 产品定位

VibeFit 是面向个人使用的训练记录工具。核心价值不是提供社交内容，而是让用户在健身过程中以尽可能少的操作完成：

- 查看今天练什么；
- 查看当前阶段和下一个动作；
- 记录重量、次数和完成状态；
- 自动进入组间休息；
- 记录跑步机、椭圆机、划船机等有氧训练；
- 在训练中断后可靠恢复；
- 在历史页复盘一次完整训练。

### 2.1 当前主要使用环境

- 竖屏手机，宽度以 360–430 CSS px 为主；
- 健身房内单手操作；
- 可能锁屏、切换应用或短暂断网；
- H5/PWA 优先，同时保证未来微信小程序 H5 和 Capacitor 容器可复用。

### 2.2 设计原则

1. **训练状态优先于装饰。** 当前训练、当前动作、当前组和休息倒计时必须清晰。
2. **完成操作必须可逆。** 误点完成组后允许取消；删除动作需要确认或放入二级菜单。
3. **业务状态不能只存在于组件本地。** 训练、组记录、有氧记录、暂停状态和恢复状态必须进入 Store 和持久化层。
4. **计时以时间戳为准。** `setInterval` 只刷新界面，不作为真实时间来源。
5. **页面切换不能丢数据。** 力量/有氧切换、底部导航切换、刷新和短时后台后都应恢复。
6. **一个屏幕只突出一个主操作。** 训练进行中时，底部主操作是“结束训练”；动作内主操作是“完成当前组”或“完成有氧记录”。

## 3. 信息架构

底部导航保留四个一级入口：

1. **今日**：执行训练和记录实时状态；
2. **计划**：选择、创建和调整训练计划；
3. **历史**：查看已结束的训练会话；
4. **设置**：单位、主题、备份、同步和账户。

“今日”页面包含两种训练模式：

- 力量；
- 有氧。

两种模式属于同一个 `TrainingSession`，不是两次独立训练。用户可在一次训练中同时完成力量和有氧。

---

## 4. 今日训练页面结构

由上到下固定为：

1. 应用标题与训练总计时；
2. 力量 / 有氧模式切换；
3. 训练上下文；
4. 训练阶段及动作卡片；
5. 底部粘性操作栏；
6. 底部主导航。

### 4.1 顶部应用栏

必须包含：

- 左：`VibeFit` 品牌字样；
- 中：`今日训练`；
- 右：训练总计时、状态点和状态文字；
- 训练中显示“训练中”；
- 整场暂停显示“已暂停”；
- 无活动会话显示“准备开始”；
- 计时区域提供暂停/继续入口，触控区域不少于 44×44 px。

训练总计时代表整场训练时长，包含正常组间休息，但不包含用户明确暂停后的时间。

### 4.2 力量 / 有氧切换

- 使用等宽双段切换控件；
- 当前模式使用品牌绿实底、白色文字；
- 非当前模式使用白底、次要文字；
- 切换模式不得结束训练、暂停训练或清空另一模式的数据；
- 有氧正在运行时切换到力量，其有氧计时继续运行；
- 力量休息计时切换到有氧后继续按时间戳计算。

### 4.3 训练上下文区

设计稿中的以下信息必须补齐：

#### 主标题行

- 训练日名称，例如：`上肢推日`；
- 训练日序号，例如：`Day 2`；
- 状态标签，例如：`进行中`；
- 可选场景图标或 emoji，但不可替代文字；
- 右侧提供“切换计划”。

#### 元信息行

- 当前周期，例如：`第 2 周 / 共 6 周`；
- 预计时长，例如：`预计 60 分钟`；
- 数据缺失时不显示占位文案“待开发”，直接隐藏该项。

#### 进度条

- 采用分段进度条；
- 分段数量优先对应训练阶段数量；
- 已完成阶段为品牌绿；
- 当前阶段为品牌绿或半完成状态；
- 未开始阶段为浅灰；
- 进度由动作/组完成数据计算，不由组件本地维护。

### 4.4 无计划状态

若没有当前训练计划：

- 不渲染虚假的阶段和动作；
- 显示清晰空状态；
- 主操作为“选择训练计划”或“创建计划”；
- 仍允许进入自由训练。

## 5. 力量训练结构

### 5.1 层级

```text
TrainingSession
└── TrainingDay
    └── TrainingPhase
        └── ExerciseGroup
            └── SessionExercise
                └── SetRecord
```

### 5.2 阶段卡片

每个阶段必须包含：

- 序号圆标；
- 阶段名称；
- 动作数量；
- 展开/收起状态；
- 完成阶段使用完成图标；
- 当前阶段默认展开；
- 已完成阶段可默认收起；
- 尚未开始阶段可收起，但用户可以手动展开。

阶段名称来自计划数据，不得根据动作名称临时推断。

### 5.3 动作组

动作组用于表达“从若干动作中选择一个或多个”的计划语义，例如：

- 胸部推举；
- 背部下拉；
- 肩后束；
- 肱三头。

在未选择动作时显示轻量添加入口，不渲染空白大卡片。添加入口文案使用：

- `添加胸部动作`；
- `添加背部动作`；
- `添加肱三头动作`。

### 5.4 动作卡片结构

展开状态必须包含：

#### 卡片头部

- 动作示意图；
- 动作名称；
- 目标肌群标签；
- 完成组数，例如 `3/4 组`；
- 组间休息配置，例如 `休息 75 秒`；
- 更多菜单；
- 展开/收起按钮。

动作示意图只是辅助，不得代替动作名称。

#### 组记录表

列固定为：

```text
组 | 重量 | 次数 | 完成
```

不在主表格中常驻删除列。删除组放入行级菜单、滑动操作或长按操作。

每行状态：

1. **已完成**：绿色组号、绿色完成按钮、浅绿色行背景；
2. **当前组**：高对比输入框，可使用品牌色边框；
3. **未来组**：灰色组号和普通输入框；
4. **禁用**：仅在业务明确禁止编辑时使用，不因“未来组”自动禁用。

输入规则：

- 重量允许小数；
- 次数只允许非负整数；
- 空值与 `0` 必须区分；
- 完成组时立即持久化；
- 取消完成时保留用户输入，只清除 `completedAt`。

#### 动作级辅助操作

- `复制上组`：复制最近一组的重量和次数，新增为未完成组；
- `添加组`：新增未完成组；
- 删除动作放入更多菜单；
- 辅助操作视觉权重低于“完成组”。

### 5.5 休息计时

- 完成一组后，在该动作卡片内显示休息计时条；
- 计时条包含：图标、`休息中`、剩余时间、`跳过`；
- 默认休息时间来自 `SessionExercise.restSeconds`；
- 缺失时使用统一常量 `DEFAULT_STRENGTH_REST_SECONDS`；
- 禁止在组件中直接写 `75`；
- 完成其他动作的组时，当前休息计时被新计时替换；
- 整场训练暂停、结束或放弃时清空休息计时；
- 倒计时使用 `endsAt - now` 计算。

## 6. 有氧训练结构

### 6.1 有氧卡片状态

有氧卡片有四种状态：

1. `idle`：未开始；
2. `running`：进行中；
3. `paused`：已暂停；
4. `completed`：当前记录已完成。

状态必须存放在 `SessionExercise.cardioRecord`，不得只存放在组件 `useState`。

### 6.2 未开始状态

显示：

- 动作名称和示意图；
- 上次记录摘要（存在时）；
- 目标时长输入；
- `开始有氧`。

单独开始有氧时必须创建或复用整场 `TrainingSession`。

### 6.3 进行中/暂停状态

显示：

- 实际时长；
- 目标时长；
- 当前器械需要的指标；
- 进行中时显示 `暂停`；
- 暂停后显示 `继续`；
- 始终提供 `完成记录`。

不同器械的指标不同：

| 器械 | 优先指标 |
|---|---|
| 跑步机 | 时长、速度、坡度、距离、卡路里 |
| 椭圆机 | 时长、阻力等级、距离、卡路里 |
| 划船机 | 时长、距离、平均配速、阻力等级 |

第一阶段允许只实现时长、速度和坡度，但数据结构不得阻止后续扩展。

### 6.4 完成状态

显示：

- 已完成时长；
- 已保存指标；
- `再次记录`。

`再次记录` 不得静默覆盖上一条记录。若当前模型只允许一条 `cardioRecord`，暂时应隐藏该按钮或明确提示“重新记录将覆盖当前记录”。后续建议将有氧记录扩展为数组。

### 6.5 有氧与历史记录

- `完成记录`只完成单个有氧动作，不等于结束整场训练；
- 只有点击底部`结束训练`后，整场 `TrainingSession` 才进入历史；
- 历史页必须读取 `cardioRecord`，不得继续从空的 `sets` 中统计有氧时长；
- 混合训练必须同时展示力量和有氧摘要；
- 有氧详情至少展示动作名称、实际时长、速度、坡度、距离和卡路里中已有的字段。

建议历史分类：

```text
strength  仅力量
cardio    仅有氧
mixed     力量 + 有氧
```

## 7. 底部粘性操作栏

位置：底部主导航上方。

### 7.1 左侧操作

力量模式：`添加动作`。

有氧模式：

- 当前版本可禁用添加按钮；
- 后续应改为`添加有氧`，而不是显示不可解释的灰色`添加动作`。

### 7.2 右侧主操作

- 无活动训练：`开始训练`；
- 有活动训练：`结束训练`；
- 存在 running/paused 有氧时，结束整场训练必须先确认：
  - 完成有氧并结束；
  - 返回继续；
  - 放弃有氧并结束。

底部粘性操作栏不得遮挡最后一张动作卡片，滚动容器底部必须预留操作栏高度与 Safe Area。

## 8. 历史页面要求

### 8.1 列表摘要

每条训练记录显示：

- 日期和时间；
- 训练日名称或`自由训练`；
- 总训练时长；
- 训练类型：力量 / 有氧 / 混合；
- 力量摘要：动作数、完成组数、训练容量（后续）；
- 有氧摘要：动作数、实际时长、距离（存在时）。

禁止使用 `session.exercises.every(e => e.type === 'cardio')` 作为唯一分类逻辑，因为混合训练会丢失有氧摘要。

### 8.2 详情

力量动作展示：

- 动作名称；
- 已完成组；
- 每组重量和次数。

有氧动作展示：

- 动作名称；
- 实际时长；
- 速度、坡度、距离、卡路里、RPE 中存在的字段。

### 8.3 数据刷新

- 进入历史页时调用 `loadSessions()`；
- 结束训练后 Store 已更新 sessions，不需要每 2 秒轮询；
- 不应通过重复调用仅执行一次的 `initialize()` 期待刷新数据；
- 页面重新获得焦点时可调用一次 `loadSessions()`。

## 9. 状态与异常处理

### 9.1 未完成训练恢复

异常中断后提供：

- 继续训练；
- 结束上次训练；
- 放弃训练。

不得因超过固定时长静默删除。

### 9.2 保存失败

- 关键操作失败时显示非阻塞错误提示；
- 保留内存中的训练数据；
- 不因同步失败阻止本地训练；
- 结束训练前应等待 pending 写队列完成，防止删除 pending 后旧写入重新创建。

### 9.3 重复开始

- 已存在 active session 时不得创建第二个 session；
- 已有有氧动作运行时，不允许启动另一个有氧动作，除非先暂停或完成当前动作；
- 禁止无提示地覆盖已完成有氧记录。

## 10. 文案规范

使用短句、动词开头：

- 开始训练
- 暂停训练
- 继续训练
- 结束训练
- 添加动作
- 完成记录
- 复制上组
- 添加组
- 跳过

避免：

- 待开发
- 点击这里
- 确定（没有上下文）
- 保存一下

时间格式：

- 整场训练：`HH:MM:SS`；
- 休息计时：`MM:SS`；
- 历史摘要可使用`42 分钟`；
- 小于 1 小时的有氧仍可使用`00:28:36`以保持运行时一致。

## 11. 数据与 UI 映射

| UI | 数据来源 |
|---|---|
| 训练日名称 | `TrainingSession.dayName` / `TrainingDay.name` |
| 训练状态 | `TrainingSession.timerStatus` |
| 总训练时长 | `elapsedSeconds + runningSince` |
| 阶段标题 | `TrainingPhase.name` |
| 动作名称 | `SessionExercise.exerciseName` |
| 目标肌群 | `Exercise.muscleGroups`，不得长期依赖名称正则推断 |
| 完成组数 | `SetRecord.completedAt` |
| 休息时间 | `SessionExercise.restSeconds` |
| 有氧状态 | `SessionExercise.cardioRecord.status` |
| 有氧实际时长 | `cardioRecord.elapsedSeconds + runningSince` |
| 历史记录 | 已结束的 `TrainingSession` |

## 13. 页面验收标准

### 今日训练

- [ ] 顶部上下文与设计稿信息层级一致；
- [ ] 页面打开后 3 秒内能判断今天练什么、当前练到哪里；
- [ ] 单手可完成记录一组、跳过休息和结束训练；
- [ ] 力量/有氧切换不丢状态；
- [ ] 组间休息真实倒计时；
- [ ] 整场暂停后总计时停止；
- [ ] 有氧暂停后有氧计时停止，但整场训练计时继续；
- [ ] 页面刷新后训练可以恢复；
- [ ] 底部操作栏不遮挡内容。

### 历史

- [ ] 结束整场训练后立即出现记录；
- [ ] 仅有氧训练显示真实时长，不显示 `0 分钟`；
- [ ] 混合训练同时显示力量和有氧摘要；
- [ ] 详情中可看到跑步机记录；
- [ ] 历史展示不依赖组件本地状态。

## 14. Agent 实施约束

开发 Agent 修改 UI 时必须遵守：

1. 先读取本文档和 `design-system.md`；
2. 不得为了对齐截图而写入无数据来源的假值；
3. 不得在多个组件重复定义颜色、圆角和尺寸；
4. 不得将业务状态退回组件本地 `useState`；
5. 不得以每秒写 Store/数据库实现计时；
6. 不得删除现有恢复、暂停和持久化语义；
7. 修改后至少验证 375×812、390×844、430×932 三种视口；
8. 所有主操作必须提供 `data-testid` 和可访问名称；
9. 设计稿无法覆盖的异常状态，以本文档的业务语义为准。
